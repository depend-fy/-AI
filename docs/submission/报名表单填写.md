## 三、作品详情（5000 字以内）

```
【作品定位】

智鉴 AI（VeriMind AI）是一个面向科研文本的事实核验 Agent。它接收论文、综述或研究报告草稿，
对其中每条事实性主张逐条核验，输出可追溯的证据链、可解释的判定与可复核的修正建议。

AI 生成的科研文本里，最危险的错误不是明显胡说，而是"看着像真的"：引用一个并不存在的 DOI、
把 2013 年发表的论文写成 2008 年、文献真实存在但没说过那句话。人工逐条核对一篇综述需要
数小时至数日，且难以保证一致性。本作品要解决的就是这个问题。

【核心功能】

1. 主张拆分：把文本拆成可独立核验的原子主张，每条给出字符级原文位置。
2. 证据核验：真实检索 Crossref、OpenAlex、arXiv 三个公开学术数据源，核对文献是否存在、
   年份与期刊是否一致；取得摘要时进一步判断文献内容是否支持该表述。
3. 六态判定与八类归因：已核实 / 存在矛盾 / 部分支持 / 来源冲突 / 证据不足 / 暂无法核验。
4. 分层判定：严格区分"文献是否存在""书目信息是否一致""内容结论是否被支持"三个层面，
   仅元数据级证据不得用于内容层面判断。
5. 修正建议：生成最小改动的修改方案（能改数字就不改整句）；改事实必须有证据，
   否则只能弱化表述或标注不确定性，不得替换为新的具体数值。
6. 独立复核：修正建议须通过独立复核（3 项确定性检查 + 2 项语义检查），
   未通过或未完成一律不写入正文。
7. 可追溯报告：每条证据带来源、层级、关系、链接与原始响应留档路径；每条结论显示命中的规则编号。

【实现方案与执行闭环】

系统采用"界面层—编排层—能力层—数据层"的分层结构，编排层由 11 步流水线组成，
完整覆盖赛题要求的五个环节：

任务规划：判定每条主张的类型，规划检索策略（DOI 精确查询 / 书目检索 / 预印本检索 /
明确不检索并说明原因）；每条主张都留下检索痕迹（查询词、命中数、未检索原因）。

工具调用：真实访问 Crossref、OpenAlex、arXiv；带最小请求间隔、结果缓存与原始响应留档。
检索失败的两种原因被严格区分——"来源明确返回不存在"与"检索本身失败"含义完全不同。

执行反馈：流水线实时回传阶段进度，每一步的输入输出均为结构化数据。

结果验证：双层验证。第一层是确定性规则表裁决，把主张与证据的匹配结果映射到六种状态、
八类问题与严重度，每条结论都带规则编号；第二层是跨厂商独立复核，
由另一家厂商的模型检查修正建议，含 3 项确定性检查与 2 项语义检查。

异常处理：模型调用失败时降级为规则引擎，并在报告中如实声明，绝不用规则结果冒充模型判断；
检索失败标注"暂无法核验"；命中缓存时标注数据来源。

在 AGH（Agnes Harness）底座环境中开发与运行，模型服务由 AGH 统一接入：
DeepSeek 为默认账号，负责主张拆分、事实审查与修正建议生成；Agnes（agnes-3.0-flash）
用于独立复核修正建议，以降低同源偏差。模型密钥由 AGH 统一管理，代码中不保存长期密钥。

【技术亮点】

1. 把"判定需要证据"做成数据契约。证据按获取深度分级（仅元数据 / 摘要 / 全文），
   判定按层面分级；数据模型在构造时即强制校验：判定为"存在矛盾""部分支持""来源冲突"时
   必须挂接至少一条证据；判定为"已核实"必须给出支持性证据；判定为"证据不足"必须写明
   还缺什么。违反即无法构造对象，从机制上杜绝"看起来有证据、其实没有"的结论。

2. 模型不作为结论来源。大模型只产出结构化判断，最终状态由可解释的规则表裁决，
   模型与规则的分歧会如实展示在报告中。

3. 跨厂商独立复核。修正由主模型提出、由另一家厂商的模型复核，
   并明确区分"改了"与"改对了"两个问题。

4. 不给假精度。不输出未经校准的"幻觉概率"或可信度评分，
   "证据不足""暂无法核验"是一等公民状态。

5. 主动公开失败。评测中的全部失败案例、指标口径与适用边界都在报告中公开。

【实验结果】

在同一批 100 条人工确认的标注用例、同一个模型的前提下，对比"直接把文本交给模型判断"（B0）
与本作品完整流程（B1）：

指标                B0 直接问模型     B1 本项目方法
精确率              61.4%            97.6%
召回率              68.6%            78.4%
F1                  64.8%            87.0%
误报率              44.9%            2.0%
六状态完全一致率    51.0%            79.0%
证据可追溯率        0.0%             69.0%
修正成功率          0.0%             79.3%
新增错误率          0.0%             0.0%

结论：直接把文本交给模型判断时，44.9% 的正确内容会被判成有问题，且每条结论都无法追问
（证据可追溯率为 0）；本方法把误报率降到 2.0%，并让 69.0% 的结论可以点开证据。
需要强调的是，B0 的错误方式是"冤枉"而不是漏检——这正是"模型自评"最不可靠的地方。

测试集覆盖 7 类用例：正确事实 15 条、明确错误事实 15 条、虚构文献 14 条、
真实文献但错误引用 14 条、证据不足 14 条、来源冲突 14 条、修正质量 14 条。
凡涉及文献的真值均经 Crossref 实测锚定（26 个候选 DOI：19 个确认存在并记录实际年份标题，
7 个确认返回 404）。

【可复现性】

245 项自动化测试全部离线可跑、零成本；静态检查零告警；
三份评测存档（B0 / B1 / 离线规则对照）随代码提供；代码经检查不含任何密钥。
代码仓库：https://github.com/depend-fy/-AI

【与常见做法的区别】

与"直接问模型"相比：本作品不把模型判断当结论。实测同批用例、同一模型下，
直接询问的误报率为 44.9%，本方法为 2.0%。

与"检索增强问答（RAG）"相比：RAG 解决的是"把相关资料喂给模型"，
本作品解决的是"这条主张到底有没有证据、证据支持到什么程度、还缺什么"，
并将其固化为可解释的规则判定与可复核的修正流程。

与"只给结论的风险评分"相比：本作品不输出未经校准的概率化评分，
而是给出六种有明确含义的状态、命中的规则编号、可点开的证据与明确写出的证据缺口。

【技术细节补充】

规则表按证据形态分族：文内自洽类（I1–I4）处理不需要外部证据的矛盾，
观点与预测类（U1）明确不判定对错，证据驱动类（E1–E7）依据证据与主张的关系下结论，
证据缺口类（N0–N6）区分"查了但不够""检索失败""来源明确不存在""没有可检索标识"等不同情形。
这样同一条状态在不同成因下都能给出不同的、可解释的理由。

证据强度分级：对已获得的证据给出 A / B / C 三级强度（A 有可引用片段且判定关系明确；
B 有元数据或两条独立来源；C 仅有线索），未获得证据时明确标注"未获证据"。
评审与使用者据此判断"这条结论的底气来自哪里"，而不是看一个笼统的可信度分数。

数据契约强制分层：证据按获取深度分为仅元数据 / 摘要 / 全文，
判定层面分为存在性 / 书目信息 / 内容一致性 / 文内自洽。
仅元数据级证据不得用于内容层面判断——这一约束写在数据模型里，违反即无法构造对象。

【发展价值与后续计划】

适用场景：期刊与会议投稿前的引用自查、学位论文的文献综述核对、
科研机构与研究团队内部的稿件质量把关、AI 辅助写作工具的输出质量校验。

后续计划：接入开放获取全文，把判定从摘要层面推进到全文层面；
引入中文文献数据源；扩充标注集并邀请不了解系统实现的人独立标注，
计算标注一致性；把规则表扩展到更多学科的证据形态。

【诚实边界】

只读到摘要，未通读全文，摘要层面的判断不等于全文核实；
中文文献无法核验（Crossref / OpenAlex 未提供中文库公开接口）；
非学术事实（政策、新闻、产品参数）需付费检索服务，当前不在覆盖范围；
作者与机构类核验尚未实现，目前仅实现年份与期刊比对；
100 条测试中 21 条状态不一致（含误报、漏判与状态不精确），已全部公开；
标注集为自建，未计算标注一致性（kappa）。
```
