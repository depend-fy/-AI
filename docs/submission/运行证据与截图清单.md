## 二、E1：AGH 执行记录（需现拍）

**为什么需要**：评审要求看到 AGH 的执行证据（模型调用了什么、每步耗时）。

**操作步骤**

1. 确认 AGH 在运行：浏览器打开 `http://127.0.0.1:4180`（AGH workbench）。
2. 在与 AGH 的对话中，让它执行本项目的可验证命令，例如：
   > 请在你当前的工作环境里依次执行以下命令并汇报输出：
   >
   > 1. `<项目目录>\.venv\Scripts\python.exe -m pytest -q`
   > 2. `<项目目录>\.venv\Scripts\python.exe scripts\run_demo.py --id real_doi_wrong_claim`
3. 等 AGH 执行完毕，打开它的**轨迹页**（trajectory），确认能看到：
   - 模型在第几步调用了哪个工具（命令行执行）
   - 每一步的耗时
   - 工具返回的结果摘要
4. **截图**：轨迹页全屏截图（含工具调用序列与耗时）。

**验收判据**

- [ ] 截图里能看出"模型 → 调用工具 → 读取结果 → 继续"的序列
- [ ] 至少有一次命令行工具调用的记录
- [ ] 能看到 AGH 的界面标识（不是自己 P 的图）

> 说明：本项目以 AGH 作为运行与调度底座；AGH 提供执行环境与调度，  
> 本项目提供核验能力。此截图用于证明 AGH 实际参与了执行过程。

## 三、E2：工具调用链（检索证据）

**取材位置**：检测报告页 —— 「证据链」区

**操作步骤**

1. 启动本项目：`powershell -ExecutionPolicy Bypass -File .\run.ps1`
2. 进入「检测工作台」→ 点「**载入示例文本**」（或首页的「**执行样例核验**」）
3. 等待完成 → 点「**查看完整报告**」
4. 找到一条**带证据的主张**（应为「存在矛盾」那条），展开证据
5. **截图**：应包含
   - 主张原文片段
   - 检索用查询词
   - 命中文献的**标题、年份、DOI、来源（Crossref / OpenAlex）**
   - 关系判定（支持 / 部分支持 / 反驳 / 无关）

**命令行版证据（更适合截图，输出干净）**

```powershell
.\.venv\Scripts\python.exe scripts\run_demo.py --id real_doi_wrong_claim
```

输出里应能看到：`外部检索：N 个查询 / M 次真实请求 / K 次命中缓存`，  
以及每条证据的来源与年份（用于证明"真实调用了外部数据源"）。

**验收判据**

- [ ] 截图里有真实来源域名或来源名称（Crossref / OpenAlex / arXiv）
- [ ] 有年份字段（这是判断"年份写错"的关键）
- [ ] 有原始响应留档路径（证明可回溯）

## 四、E3：Agnes 参与核心任务的证据（独立复核）

**取材位置**：检测报告页 —— 「**修正建议与独立复核**」区

**操作步骤**

1. 在报告页向下滚动到「修正建议与独立复核」
2. 展开该条修正
3. **截图**：应包含五项检查的**逐项结论与理由**：
   1. 修正内容是否有证据支持
   2. 证据与修正后表述是否匹配
   3. 是否引入新的事实错误
   4. 原始问题是否已解决
   5. 是否出现新的无依据结论
4. 同时截图报告页顶部的**运行模式**标注（应为「多模型协同」）

**实测参考**（`real_doi_wrong_claim` 的真实结论）

```
[K001] 已采用｜更正数字
    原文：2008 年  →  改为：2013 年
    复核：通过但有风险
      [OK] 修正内容是否有证据支持：已引用 2 条证据（E003、E004）
      [OK] 证据与修正后表述是否匹配：新事实均能在所引证据中找到对应内容
      [OK] 是否引入新的事实错误：没有引入原文与全部证据之外的新事实
      [OK] 原始问题是否已解决：Crossref 与 OpenAlex 均记录为 2013 年
      [OK] 是否出现新的无依据结论：未引入新的定性结论
```

**验收判据**

- [ ] 五项检查全部可见（不是一句"复核通过"）
- [ ] 复核结论里有具体的理由文字
- [ ] 页面显示了独立复核模型来自另一家厂商（agnes）
