## 一、正常样例（期望：系统正确判定）

### 样例 N1｜真实 DOI + 正确年份 → 已核实

```
输入：LeCun、Bengio 与 Hinton 的深度学习综述发表于 2015 年（DOI: 10.1038/nature14539）。
期望：已核实
实际：已核实 ✓  命中规则 E5，证据 E001（Crossref）/ E002（OpenAlex）
```

### 样例 N2｜真实 DOI + 正确年份（跨学科：温度测量）

```
输入：Nanometre-scale thermometry in a living cell（DOI: 10.1038/nature12373）发表于 2013 年。
期望：已核实
实际：已核实 ✓  命中规则 E5
```

### 样例 N3｜真实 DOI + 正确年份（跨学科：科学计算）

```
输入：Array programming with NumPy（DOI: 10.1038/s41586-020-2649-2）发表于 2020 年。
期望：已核实
实际：已核实 ✓  命中规则 E5
```

### 样例 N4｜真实 DOI + 错误年份 → 存在矛盾

```
输入：LeCun、Bengio 与 Hinton 的深度学习综述发表于 2008 年（DOI: 10.1038/nature14539）。
期望：存在矛盾（时间、人物或机构信息错误）
实际：存在矛盾 ✓  命中规则 E2，两个独立来源均记录为 2015 年
```

### 样例 N5｜虚构 DOI（格式合规但未注册）→ 存在矛盾

```
输入：据一项发表于 2023 年的研究（DOI: 10.1126/science.169.3946.1071）显示，该方法可将训练成本降低 70%。
期望：存在矛盾（引用不存在或元数据不匹配）
实际：存在矛盾 ✓  Crossref 与 OpenAlex 均返回 404；证据保留"来源明确不存在"的状态
```

## 二、边界样例（期望：系统给出保守、诚实的判定）

### 样例 B1｜没有可检索标识的模糊引用 → 证据不足

```
输入：多项研究表明，该方法的准确率显著优于现有方案。
期望：证据不足（缺少必要证据）
实际：证据不足 ✓  命中规则 N1；报告写明"还缺可核验的文献标识"
说明：系统不会因为查不到就判定内容有错——"无证据 ≠ 错误"。
```

### 样例 B2｜带具体数字但无出处 → 证据不足

```
输入：据统计，该行业市场规模在 2023 年已达到 1200 亿元。
期望：证据不足
实际：证据不足 ✓  命中规则 N1
```

### 样例 B3｜预测类内容 → 暂无法核验（不是"证据不足"）

```
输入：业内专家普遍认为，该技术将在五年内全面普及。
期望：暂无法核验（观点/预测类不属于可用事实证据核验的内容）
实际：暂无法核验 ✓  命中规则 U1
说明：这条边界很重要——"证据不足"指可核验但缺证据，"暂无法核验"指本身不该用事实证据判对错。
      两者在系统里是不同状态，理由也不同。
```

### 样例 B4｜中文文献来源 → 暂无法核验

```
输入：国内多所高校的研究团队已对该方法进行了系统验证（中文期刊，无 DOI）。
期望：暂无法核验
实际：暂无法核验 ✓
说明：Crossref / OpenAlex 未提供中文库公开接口，系统如实标注无法核验，
      不假装查过，也不因为"查不到"而判其有错。
```

### 样例 B5｜文内自相矛盾（无需外部证据）→ 来源冲突

```
输入：该文献（DOI: 10.1038/nature14539）发表于 2015 年。同一篇 2001 年的论文（DOI: 10.1038/nature14539）给出了类似结论。
期望：来源冲突（不同来源之间存在冲突）
实际：来源冲突 ✓  该矛盾来自原文自身，无需任何外部证据即可确认
```

### 样例 B6｜数据不可得 → 如实标注而非猜测

```
输入：该研究发表于 2023 年（DOI: 10.1234/nonexistent.2023.001），样本量为 5000 例。
期望：存在矛盾（DOI 未注册）
实际：存在矛盾 ✓  "样本量 5000 例"这条另行标注证据不足
说明：系统把一条主张拆成可分别核验的原子主张，能核的先核，不能核的如实标注，不合并成一句笼统结论。
```

## 三、失败样例（系统真实判错的案例，全部公开）

> 以下 6 条来自 100 条标注集的实测结果：**23 条状态不一致**中的代表案例。
> 公开这些案例是本项目的设计原则之一——失败必须可见，否则指标没有意义。

### 样例 F1｜漏检最严重：年份写错却判成"已核实"

```
输入：Human-level control through deep reinforcement learning（DOI: 10.1038/nature14236）发表于 2001 年。
标注：存在矛盾　　实际：已核实 ✗
性质：**漏检**——该文献实际发表于 2015 年，系统未能据此证伪。
```

### 样例 F2｜漏检：年份写错却判成"已核实"

```
输入：Array programming with NumPy（DOI: 10.1038/s41586-020-2649-2）发表于 2001 年。
标注：存在矛盾　　实际：已核实 ✗
性质：漏检（该文献实际发表于 2020 年）
```

### 样例 F3｜漏判：可核验却停在"证据不足"

```
输入：Long Short-Term Memory（DOI: 10.1162/neco.1997.9.8.1735）发表于 1997 年。
标注：已核实　　实际：证据不足 ✗
性质：**漏判**——年份本可核验（且正确），系统却未能完成核验。
```

### 样例 F4｜漏判：内容主题错配未被识别

```
输入：一项发表于 1997 年的研究（DOI: 10.1162/neco.1997.9.8.1735）提出了 Transformer 架构。
标注：已核实（DOI 与年份层面）　　实际：证据不足 ✗
性质：漏判——年份层面的核验未完成；内容层面（该文献并未提出 Transformer）
      属于已知局限：需要摘要或全文才能判断。
```

### 样例 F5｜误报：把正确内容说得过重

```
输入：Hochreiter 与 Schmidhuber 提出的长短期记忆网络发表于 1997 年（DOI: 10.1162/neco.1997.9.8.1735）。
标注：已核实　　实际：部分支持 ✗
性质：**误报**——内容本身正确，系统只拿到部分证据却给了偏重的问题判定。
      误报比漏判更伤用户信任，因此本作品把误报率作为最核心的诚实指标。
```

### 样例 F6｜状态不精确：判断方向对、类型错

```
输入：长短期记忆网络（LSTM）由 Hochreiter 与 Schmidhuber 于 2005 年提出（DOI: 10.1162/neco.1997.9.8.1735）。
标注：存在矛盾　　实际：部分支持 ✗
性质：状态不精确——确实指出了可疑，但未准确落到"存在矛盾"。
```

## 四、三类样例汇总

| 类别 | 样例数 | 系统表现 | 说明 |
|---|---|---|---|
| **正常** | 5 | 全部判定正确 | 覆盖正确事实、错误年份、虚构 DOI 三种典型情形 |
| **边界** | 6 | 全部给出保守且诚实的判定 | 覆盖模糊引用、无出处数字、预测类、中文来源、文内矛盾、部分可核 |
| **失败** | 6 | **真实判错，已公开** | 覆盖漏检 2 条、漏判 2 条、误报 1 条、状态不精确 1 条 |

**全量实测指标（100 条标注集）**：精确率 97.6% / 召回率 78.4% / F1 87.0% /
**误报率 2.0%** / 六状态完全一致率 79.0% / 证据可追溯率 69.0%。

## 五、如何自行复现这些样例

```powershell
cd <项目目录>

# 跑单条样例（命令行）
.\.venv\Scripts\python.exe scripts\run_demo.py --id real_doi_wrong_claim   # 样例 N4 类
.\.venv\Scripts\python.exe scripts\run_demo.py --id mixed_status_demo      # 综合样例

# 跑全量 100 条评测（含全部失败案例明细）
.\.venv\Scripts\python.exe scripts\run_evaluation.py --baseline b1 --all

# 查看失败案例清单（评测页「详细数据 → 失败案例」）
powershell -ExecutionPolicy Bypass -File .\run.ps1
```
