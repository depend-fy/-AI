# 演示视频录制全流程（逐步操作 + 验证清单）

> 赛事要求：3–5 分钟演示视频，随作品一并提交。
> 评审重点：问题价值与学科融合、任务完成度与结果正确性、Harness 与模型执行闭环、
> 技术深度、验证严谨性、异常处理、创新性及发展价值。
>
> 本指南中的**所有数值均为实测**（录制前用命令行核对过），可直接用于对照。

---

## 阶段 0｜T-60 分钟：环境验证（4 条命令，逐条核对）

```powershell
cd <你的项目目录>\verimind-ai
```

### 0.1 环境自检

```powershell
.\.venv\Scripts\python.exe scripts\check_env.py
```

**预期**：Python 版本、依赖、数据目录、配置项逐项显示 OK。
**不通过就先别录**——环境问题会中断录制。

### 0.2 模型连通性（最关键）

```powershell
.\.venv\Scripts\python.exe scripts\check_llm.py
```

**必须验证的 3 点**：
1. 运行模式显示 **「多模型协同」**（不是"离线模拟"）——否则视频里"跨厂商独立复核"就是假的；
2. 生成模型为 `deepseek/deepseek-chat`、独立复核模型为 `agnes/agnes-3.0-flash`；
3. 状态为可调用（无鉴权/额度报错）。

> ⚠️ 如果这里显示"离线模拟"，请先配置 `.env` 再录，不要带着降级状态录。

### 0.3 预热缓存（决定录制是否流畅）

```powershell
.\.venv\Scripts\python.exe scripts\run_demo.py --id mixed_status_demo
.\.venv\Scripts\python.exe scripts\run_demo.py --id real_doi_wrong_claim
```

**预期**：两次都显示 `大模型调用：0 次计费 / N 次命中缓存`、耗时 200–300 ms。
**这一步的作用**：录制时界面点击是秒级响应，不会出现等待圈。

### 0.4 测试全绿

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

**预期**：`245 passed`。
**为什么要确认**：视频里要闪过"245 项测试"这个数字，**必须与真实结果一致**。

这一段是**最容易被跳过、也最影响成片**的。请按下面的表逐条确认：

| # | 要出现的画面 | 如何确认 | 实测应为 |

| 6 | 报告：状态徽标 | 报告页顶部 | 内置样例：**存在矛盾 = 1，证据不足 = 5**；规则 **E3**（真实DOI样例为 **E5 + E2 + N6×3**） |
| 7 | 报告：证据可点开 | 展开第一条证据 | 显示来源（Crossref / OpenAlex）、年份、DOI、**可点击链接**、原始响应留档 |

| 9 | 报告：「适用范围与局限」 | 报告页下滚 | 明确列出只读摘要、中文文献不可核验等 |
| 10 | 评测页：核心对比表 | 进入评测页 | **B0 直接问模型 vs B1 本项目方法**（B0 误报率 **44.9%**，B1 **2.0%**） |
| 11 | 评测页：失败案例 | 评测页下滚 | **21 条**失败案例清单（状态不一致） |

### ⚠️ 必须提前知道的一件事

**修正的复核结论不是固定的**（由独立复核模型给出）。实测两个样例当前都是**「已采用」**：

| 样例 | 复核结论 | 含义 |
|---|---|---|
| `mixed_status_demo` | **通过** | 修正 2005 → 1997 被采用 |
| `real_doi_wrong_claim` | **通过但有风险** | 修正 2008 → 2013 被采用，且复核**明确指出**该 DOI 的真实标题与原文主题不符 |

**因此旁白不要说"复核员否决了这条修正"**（那是不准确的）。正确说法见下文第 4 段旁白。

## 阶段 3｜分段录制（按幕操作，每幕含验证点）

**验证点**：
- [ ] 题头显示的是「面向科研文本的事实核验 Agent」（不是"AI 幻觉检测系统"）

**旁白**：见《演示视频脚本》第 1 段全文。

### 第 2 段｜任务定义（0:30–0:50）

**操作**：首页缓慢下滚，鼠标划过「任务闭环对照」表。

**画面应出现**：五环节表格逐行进入画面。

**验证点**：
- [ ] 表格 5 行齐全：任务规划 / 工具调用 / 执行反馈 / 结果验证 / 异常处理

**旁白**：见脚本第 2 段。

### 第 3 段｜闭环演示（0:50–2:40）— **核心段落**

**操作步骤**：

1. 左侧导航点「**检测工作台**」
2. 点「**载入示例文本**」（或直接从首页点「**执行样例核验**」）
3. 点「**开始核验**」→ 进度推进
4. 展开「**阶段明细**」面板（停留约 2 秒）
5. 完成后点「**查看完整报告**」
6. 报告页：从上往下缓慢滚动
7. 停在**存在矛盾**那条主张 → 展开**证据**（鼠标停在 Crossref/OpenAlex 链接上）
8. 停在**证据不足**那条（N6/N1）
9. 滚到「**修正建议与独立复核**」→ 展开**五项复核结论**

**画面应出现**（对照实测值）：

| 位置 | 应显示 |
|---|---|
| 结论摘要 | 主张总数 **6**；已判定有问题 **1** |
| 状态徽标 | 存在矛盾 **1**、证据不足 **5**（内置样例） |
| 命中规则 | **E3**（真实 DOI 样例：**E5 / E2 / N6**） |
| 修正 | **1 条**，状态「**已采用**」 |
| 复核 | 「**通过**」（真实 DOI 样例为「通过但有风险」） |
| 底部 | 数据来源标注（本地缓存）+ 耗时 + 调用次数 |

**验证点**：
- [ ] 证据条目里能看到**真实来源域名**（api.crossref.org / api.openalex.org）
- [ ] 证据条目显示**年份**（这是判断"2008 年"错误的关键）
- [ ] 有一条被判「**证据不足**」——这是诚实性的体现，**不能剪掉**
- [ ] 复核结论逐项列出（5 项检查）

**旁白（重要修正）**：

> 这是本项目最关键的设计：修正建议必须通过独立复核。
> 修正员提出把年份从 2008 改为 2013。独立复核员逐项检查：修改有证据支持、与证据匹配、未引入新事实；
> 同时**明确指出它解决不了的风险**——该 DOI 的真实标题与原文声称的研究主题不符，
> 只改年份并不能修正这个文献对应关系。风险被写进报告。
> **复核不是盖章：它必须说明这项修改解决了什么、又留下了什么没解决。**

**验证点**：

## 常见问题与预案

| 情况 | 预案 |
|---|---|
| 点「开始核验」后进度卡住 | 大概率是缓存未命中在真实调用模型。**等待**即可；若超过 60 秒，切到报告页看历史记录，或改用另一个样例。**不要重录整段**，只重录这一幕。 |
| 运行报错（红框） | 千万别剪掉藏着——**这是异常处理的素材**。可以顺势说明："系统在这个位置如实报告了失败原因，而不是返回一个看起来正常的结论。"（前提是确实如此） |
| 网络中断 | 系统会降级并声明；如实拍下来，配合第 5 段旁白说明"检索失败不等于内容有问题"。 |
| 复核结论与预期不同 | **以画面为准**，旁白按"五项检查 + 指出风险"的说法讲，不要念固定的"否决"。 |
| 数字与指南不一致 | 以**屏幕上显示的**为准（模型输出有波动）。旁白避免念具体小数，多说量级与关系。 |
| 说错词 | 分段录制，只重录那一段。 |
