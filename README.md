# 智鉴 AI（VeriMind AI）

> 多模型协同的 AI 幻觉检测、证据溯源、错误归因与自动修正系统 —— **Demo 版**

把「相信一个模型」换成「一条可审计的校验流水线」：每条结论都能追问一句 **"你凭什么这么说？"**

### 现在能做什么

1. 用**真实大模型**把文本拆解成可单独核验的原子事实主张（含精确到字符的原文位置）；
2. **同时**用规则引擎独立拆解一遍，两个引擎的差异全部写进报告的「引擎交叉比对」——
   谁多发现了什么、谁漏了什么、谁怀疑什么但规则层不确认，一条都不隐藏；
3. 检查**原文内部的矛盾**：同一 DOI 两个年份、同一指标两个数值 → 来源冲突（无须外部证据）；
4. 事实审查员（角色 A）逐条审查并给出怀疑方向；最终状态仍由**可解释的规则表**裁决；
5. 模拟的 6 种核验状态、8 类问题类型、每条主张配「判断理由 + 命中的规则 + 还缺什么证据」；
6. 真实记录 token 用量与耗时；配置单价后可估算成本；
7. 结果缓存到本地（同一输入重跑**不花钱**）、报告存入 SQLite、可导出 JSON。

### 现在还不能做什么（重要）

| 做不到的事 | 什么时候能补上 |
| --- | --- |
| 查文献是否真实存在、年份是否一致 | 阶段 4 |
| 判断论文是否支持某个结论 | 阶段 4（摘要）/ 阶段 5（全文） |
| 生成修正建议、复核修正结果（角色 B / C） | 阶段 5 |
| 在人工标注集上给出精确率、误报率 | 阶段 6 |

> 因此报告里**不会出现「已核实」**，也不会因为外部证据出现「存在矛盾」——
> 因为还没有查过任何外部来源。没有证据就说「已核实」，是本项目最不能接受的事。

## 二、快速开始（Windows / PowerShell）

```powershell
cd <项目目录>

# 1) 环境自检（含大模型密钥连通性，会发一次极小请求）
.\.venv\Scripts\python.exe scripts\check_env.py --network
.\.venv\Scripts\python.exe scripts\check_llm.py

# 2) 不开网页先跑一遍（推荐先做这步）
.\.venv\Scripts\python.exe scripts\run_demo.py --list
.\.venv\Scripts\python.exe scripts\run_demo.py --id internal_conflict

# 3) 启动界面
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

浏览器打开后：首页 → 「检测工作台」载入示例 → 「开始检测」→ 「检测报告」。

### 环境自检脚本

| 脚本 | 检查什么 |
| --- | --- |
| `scripts/check_env.py --network` | Python 版本、依赖、配置、数据目录、Crossref/OpenAlex/arXiv 连通性 |
| `scripts/check_llm.py` | 大模型密钥是否被读到（**只显示脱敏值**）、发一次极小请求验证可用性，并对 401/402/404/超时给出处理建议 |
| `scripts/run_demo.py` | 命令行完整跑一次检测并打印报告（断网也能用作离线演示） |

## 三、4 条示例的真实运行结果（真实模型 deepseek-chat，非设计目标）

| 示例 | 演示什么 | 真实结果 |
| --- | --- | --- |
| `fake_doi` | 虚构 DOI + 数值夸大 | 模型拆出 **6 条**主张（规则引擎 3 条）。DOI 格式不合规 → `N5`（疑似引用不存在，中）；`提高 40%` 无出处 → `N2`（缺少必要证据，中）；因果类结论 → `N3`（逻辑推断过度，中） |
| `real_doi_wrong_claim` | 真实存在的 DOI + 可疑年份与结论 | 模型拆出 **6 条**主张，全部「证据不足」、**零可疑标记**——因为阶段 3 还没查过这个 DOI，系统拒绝下结论 |
| `insufficient_evidence` | 模糊权威 + 预测 | **3 条**判为「暂无法核验」（观点/预测，`U1`，**不判成事实错误**）；「多项研究表明」→ `N4`、「因果结论」→ `N3`+`N4` |
| `internal_conflict` | 文内自相矛盾 | 模型拆出 **7 条**，其中 **4 条「来源冲突」**（同一 DOI 两个年份 → `I1`；同一指标两个数值 → `I2`），严重度高，证据来自原文自身；期刊类/DOI/归属类 3 条如实标为「证据不足」 |

**实测性能与成本数据**（来自本地 `llm_calls` 表，不是估算）：

| 指标 | 实测值 |
| --- | --- |
| 单次检测计费调用次数 | 2 次（主张拆解 + 事实审查） |
| 单次检测 token | 约 2,900 – 4,200（prompt 约 950–1,900 / completion 约 400–1,200） |
| 单次检测耗时 | 约 9.2 – 9.6 秒（拆解 2.5–4 秒 + 事实审查 5–6.4 秒） |
| **第二次运行同一文本** | **0 次计费调用、0 token、约 0.25 秒**（命中本地缓存） |
| 阶段 3 开发期累计消耗 | 8 次计费调用，prompt 10,641 + completion 6,396 = **17,037 tokens** |
| 金额 | **未计算**——项目不内置任何单价；在 `.env` 填单价后才显示（见第七节） |

## 六、裁决规则表（报告里会原文展示命中的规则）

**可解释性是本项目的核心设计**：大模型只输出结构化的"怀疑方向"，
「这条主张到底算不算有问题」由下表决定。因此每条结论都能说清"凭什么"。

| 规则 | 条件 | 结论 |
| --- | --- | --- |
| `I1` | 同一 DOI 在原文中被写成两个不同年份 | 来源冲突（证据来自原文自身，严重度高） |
| `I2` | 同一指标在原文中出现两个不同数值 | 来源冲突（证据来自原文自身，严重度高） |
| `U1` | 观点 / 预测类内容 | 暂无法核验（**不判成事实错误**） |
| `N1` | 需要外部证据，但本次未启用检索 | 证据不足（**不附带任何问题类型**——"还没查"不等于"有问题"） |
| `N2` | 主张片段里**确实含数值**，整句却没有可核验出处 | 证据不足 + 缺少必要证据 |
| `N3` | 强因果 / 结论性表述，却没有具体来源 | 证据不足 + 逻辑推断过度 |
| `N4` | 用「大量研究表明」这类模糊表述支撑结论 | 证据不足 + 缺少必要证据 |
| `N5` | DOI 格式不合法（前缀应为 4~9 位数字） | 证据不足 + 引用不存在或元数据不匹配（**疑似，未证实**） |

## 七、配置说明（`.env`）

配置项统一以 `VERIMIND_` 开头；`.env` 已被 `.gitignore` 忽略，**不会提交到 Git**。

```ini
# 大模型：换供应商只改这三行，代码不用动
VERIMIND_LLM_PROVIDER=deepseek                       # mock / deepseek / zhipu / moonshot / dashscope / openai / ollama
VERIMIND_LLM_BASE_URL=https://api.deepseek.com/v1
VERIMIND_LLM_MODEL=deepseek-chat
VERIMIND_LLM_API_KEY=sk-...                          # 留空 = 自动进入离线模拟模式

# 独立复核员（可选）：三项都填且与主模型不同 → 升级为"多模型协同"
VERIMIND_LLM_REVIEWER_PROVIDER=
VERIMIND_LLM_REVIEWER_MODEL=
VERIMIND_LLM_REVIEWER_API_KEY=

# 成本与稳定性
VERIMIND_LLM_TIMEOUT_SECONDS=60
VERIMIND_LLM_MAX_RETRIES=2
VERIMIND_LLM_CACHE_ENABLED=true                      # 相同输入复用缓存，重跑不花钱
VERIMIND_LLM_MAX_CALLS_PER_RUN=30                    # 单次检测调用硬上限

# 成本估算（**故意留空**：没有单价就不显示金额，绝不编一个数字）
VERIMIND_LLM_PRICE_PROMPT_PER_MTOK=                  # 每百万 prompt token 多少元（查官网填）
VERIMIND_LLM_PRICE_COMPLETION_PER_MTOK=
```

填单价后，报告与「检测报告」页会显示按实测 token 计算的成本，并注明"单价来自 .env，请自行核对"。

> ⚠️ **编辑 `.env` 请用记事本或 VS Code，保存为 UTF-8**。
> Windows PowerShell 的 `Set-Content` 在某些环境下默认使用 GBK 编码，会把文件里的中文注释写坏
> （开发期真实踩过这个坑）。用记事本保存没有任何问题。

## 八、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 报错「已选择 provider=... 但没有配置 API Key」 | 在 `.env` 填 `VERIMIND_LLM_API_KEY`，或把 provider 改回 `mock` |
| 报错 HTTP 401 | 密钥无效或已失效（运行 `scripts/check_llm.py` 会直接告诉你） |
| 报错 HTTP 402 | 账户余额不足 |
| 报错 HTTP 404 | 模型名或接口地址不对，核对 `VERIMIND_LLM_MODEL` / `VERIMIND_LLM_BASE_URL` |
| 报告顶部出现「⚠️ 本次已降级为离线规则引擎」 | 模型调用失败（超时/限流/格式连续不合格），系统自动降级**并声明原因**，不会假装调用成功 |
| 报告里说「N 次命中缓存」 | 同一段文本之前跑过；缓存键包含提示词版本，改了提示词会自动失效 |
| 报告里为什么没有「已核实」 | 阶段 3 还没接入外部检索。没有证据不说「已核实」是刻意设计 |
| 为什么有些主张标了问题类型却不叫「已判定有问题」 | 「已判定有问题」只统计状态为存在矛盾/部分支持/来源冲突的；其余是「需关注」（疑似或证据缺口），两个数字分开显示，避免夸大检测能力 |
| 命令行中文乱码 | `chcp 65001`，或用 `.\run.ps1` 启动（已自动处理） |
| 端口被占用 | `--server.port 8600` 换端口 |

## 九、设计原则（贯穿整个项目）

1. **证据可追溯**：每条判断都要能点开到真实来源；报告里不出现无法解释的结论。
2. **模型不下最终结论**：模型只输出结构化判断与"怀疑方向"，状态由可解释的规则表裁决。
3. **暴露分歧，不掩盖分歧**：规则引擎与模型谁多发现了什么、谁漏了什么，全部写进报告。
4. **无证据不判错**：「证据不足 / 暂无法核验」是一等公民，绝不为了凑结论把"查不到"说成"错误"。
5. **失败要说出来**：模型调用失败就明确降级并声明原因，绝不悄悄用规则结果冒充模型结果。
6. **不假装读过全文**：证据必须标注内容层级（仅元数据 / 摘要 / 全文 / 用户原文）。
7. **不给假数字**：没有校准过的概率就不给"幻觉分数"；没有配置单价就不给成本金额；只报真实 token 与耗时。
8. **不注水**：一句话不会拆成好几条同义主张；宁可报"需要关注"，也不虚报"已判定有问题"。
9. **密钥安全**：密钥不写入代码、不进 Git、不出现在日志与报告中（日志只记提示词哈希）。

## 十、免责声明

本项目为 Demo，用于方法验证与竞赛演示。系统输出是基于可检索公开证据的**辅助判断**，
不构成学术结论、法律意见或事实认定的最终依据。系统无法确知其他模型内部真实的出错原因；
报告中的问题类型是系统依据**可观察证据**作出的归因。
