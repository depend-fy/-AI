# 智鉴 AI（VeriMind AI）

> 多模型协同的 AI 幻觉检测、证据溯源、错误归因与自动修正系统 —— **Demo 版**

把「相信一个模型」换成「一条可审计的校验流水线」：每条结论都能追问一句 **"你凭什么这么说？"**

### 现在能做什么

1. 把一段文本拆解成**可单独核验的原子事实主张**（含精确到字符的原文位置）；
2. 识别 DOI、年份、具体数值、因果表述、模糊引用、观点预测等关键要素；
3. 检查**原文内部的矛盾**——同一文献被写成两个年份、同一指标出现两个数值。
   这类矛盾不需要任何外部证据就能确认；
4. 对每条主张给出：核验状态、问题类型、判断理由、**命中的规则编号**、以及「还缺什么证据」；
5. 把完整报告存进本地 SQLite，可随时回看、导出 JSON。

### 现在还不能做什么（重要）

| 做不到的事 | 什么时候能补上 |
| --- | --- |
| 调用真实大模型（现在用的是正则规则引擎） | 阶段 3 |
| 查文献是否真实存在、年份是否一致 | 阶段 4 |
| 判断论文是否支持某个结论 | 阶段 4（需要摘要）/ 阶段 5（需要全文） |
| 生成修正建议、复核修正结果 | 阶段 5 |
| 在人工标注集上给出指标（精确率、误报率等） | 阶段 6 |

> 因此现在报告里**不会出现「已核实」**，也不会因为外部证据出现「存在矛盾」——
> 因为还没有查过任何外部来源。没有证据就说「已核实」，是本项目最不能接受的事。

## 二、快速开始（Windows / PowerShell）

在项目根目录依次执行：

```powershell
# 1) 一键启动（推荐；会自动切 UTF-8 并检查环境）
powershell -ExecutionPolicy Bypass -File .\run.ps1

# 2) 或者手动启动
.\.venv\Scripts\python.exe -m streamlit run app.py
```

启动后浏览器会自动打开 <http://127.0.0.1:8501>。

**应该看到什么**：

- 首页：标题「🔍 智鉴 AI（VeriMind AI）」+ 顶部灰色提示条
  **「当前运行模式：离线模拟」**（因为还没配置大模型密钥，系统如实标注）；
- 「检测工作台」：4 个示例文本一键载入按钮 + 输入框 + 「开始检测」，
  点击后能看到分步进度；检测完显示结果摘要；
- 「检测报告」：统计卡片、原文高亮、逐条主张卡片
  （原文位置 → 规范化主张 → 核验问题 → 判断理由 → 命中规则 → 证据 → 还缺什么）、
  系统局限、导出 JSON；
- 「评测」：仍是**诚实占位页**（真实指标要等阶段 6）。

## 三、4 条示例文本（`examples/sample_inputs.jsonl`）的真实运行结果

以下数字来自**本机实际运行**（阶段 2，离线规则引擎），不是设计目标：

| 示例 | 演示什么 | 实际结果 |
| --- | --- | --- |
| `fake_doi` | 虚构 DOI + 数值夸大 | 3 条主张；DOI 格式不合规 → 命中 `N5`（疑似引用不存在，严重度中）；`40%` 无出处 → 命中 `N2`（缺少必要证据） |
| `real_doi_wrong_claim` | 真实存在的 DOI + 可疑年份与结论 | 4 条主张；全部为「证据不足」，**没有任何可疑标记**——因为阶段 2 还没查过这个 DOI，不能下结论 |
| `insufficient_evidence` | 模糊权威 + 预测 | 2 条主张：「多项研究表明…」→ 命中 `N3`+`N4`（推断过度 + 缺少必要证据）；预测部分 → `U1`「暂无法核验」（**不判成事实错误**） |
| `internal_conflict` | 文内自相矛盾 | 5 条主张；同一 DOI 两个年份 → `I1`、同一指标两个数值 → `I2`，共 4 条「来源冲突」（严重度高），证据来自**原文自身**；DOI 本身仍如实标为「证据不足」 |

## 六、裁决规则表（报告里会原文展示命中的规则）

**可解释性是本项目的核心设计**：大模型（或规则引擎）只产出结构化信号，
「这条主张到底算不算有问题」由下面这张表决定。因此每条结论都能说清"凭什么"。

| 规则 | 条件 | 结论 |
| --- | --- | --- |
| `I1` | 同一 DOI 在原文中被写成两个不同年份 | 来源冲突（证据来自原文自身，严重度高） |
| `I2` | 同一指标在原文中出现两个不同数值 | 来源冲突（证据来自原文自身，严重度高） |
| `U1` | 观点 / 预测类内容 | 暂无法核验（**不判成事实错误**） |
| `N1` | 需要外部证据，但本次未启用检索 | 证据不足（**不附带任何问题类型**——"还没查"不等于"有问题"） |
| `N2` | 给出了具体数值，整句却没有可核验出处 | 证据不足 + 缺少必要证据 |
| `N3` | 用了「证明 / 证实 / 充分说明」却无具体来源 | 证据不足 + 逻辑推断过度 |
| `N4` | 用「大量研究表明」这类模糊表述支撑结论 | 证据不足 + 缺少必要证据 |
| `N5` | DOI 格式不合法（前缀应为 4~9 位数字） | 证据不足 + 引用不存在或元数据不匹配（**疑似，未证实**） |

## 八、配置说明

配置全部通过**环境变量或 `.env` 文件**提供，变量名统一以 `VERIMIND_` 开头。

```powershell
Copy-Item .env.example .env    # 然后编辑 .env
```

- `.env` 已被 `.gitignore` 忽略，**不会提交到 Git**；
- 界面上只显示脱敏后的密钥（如 `sk-****abcd`）；报告只记录 provider 与 model 名；
- `VERIMIND_LLM_PROVIDER=mock`（默认）时完全不调用真实模型；
- 阶段 2 若配置了真实 provider，检测会**明确报错**并提示改回 `mock`，
  而不是偷偷用规则引擎顶替（阶段 3 接好适配器后即可正常使用）。

## 九、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 命令行中文乱码 | 终端代码页不是 UTF-8。执行 `chcp 65001`，或用 `.\run.ps1` 启动（已自动处理） |
| `streamlit : 无法将"streamlit"项识别为...` | 用模块方式运行：`.\.venv\Scripts\python.exe -m streamlit run app.py` |
| 端口被占用 | `--server.port 8600` 换端口 |
| 检测报错「尚未接入真实模型调用」 | `.env` 里设了真实 provider。阶段 2 请用 `VERIMIND_LLM_PROVIDER=mock` |
| 报告里为什么没有「已核实」 | 因为阶段 2 没有查过任何外部来源。没有证据不说「已核实」是刻意设计 |
| 为什么有的主张标了问题类型却不叫「可疑」 | 「已判定有问题」只统计状态为存在矛盾/部分支持/来源冲突的；其余是「需关注」（疑似或证据缺口）。两个数字分开显示，避免夸大检测能力 |
| PowerShell 禁止运行脚本 | 用 `powershell -ExecutionPolicy Bypass -File .\run.ps1` |
| Python 3.15 装不上某些库 | 本项目虚拟环境固定用 **3.13**（`py -3.13 -m venv .venv`） |

## 十、设计原则（贯穿整个项目）

1. **证据可追溯**：每条判断都要能点开到真实来源；报告里不出现无法解释的结论。
2. **模型不下最终结论**：模型只输出结构化判断，状态由可解释的规则表裁决。
3. **无证据不判错**：「证据不足 / 暂无法核验」是一等公民，绝不为了凑结论把"查不到"说成"错误"。
4. **不假装读过全文**：证据必须标注内容层级（仅元数据 / 摘要 / 全文 / 用户原文）。
5. **不给假概率**：没有校准过的概率模型，就不显示貌似精确的「幻觉分数」。
6. **不注水**：一句话不会拆成好几条同义主张来显得"检出很多问题"；宁可报"需要关注"，也不虚报"已判定有问题"。
7. **不虚构数据**：不编造文献、DOI、页码、实验数据；页面上的指标必须来自真实运行。
8. **密钥安全**：密钥不写入代码、不进 Git、不出现在日志与报告中。
