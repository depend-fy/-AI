### 现在能做什么

1. 用**真实大模型**把文本拆解成可单独核验的原子事实主张（含精确到字符的原文位置）；
2. **同时**用规则引擎独立拆解一遍，两个引擎的差异全部写进报告的「引擎交叉比对」；
3. 真的去 **Crossref / OpenAlex / arXiv** 检索文献，核验「文献是否存在」「年份/期刊是否一致」，
   并在拿到摘要时判断「内容结论是否被支持」（必须引用摘要原句才算数）；
4. 检查**原文内部的矛盾**（同一 DOI 两个年份、同一指标两个数值）；
5. 角色分工：事实审查员（该查什么）、证据审查员（证据说了什么）、
   修正员（最小改动建议）、独立复核员（从怀疑立场审查修正）；
   最终状态仍由**可解释的规则表**裁决；
6. **只采用复核通过的修正**：复核员的语义判断 + 三项确定性检查（是否有证据、是否与证据匹配、是否凭空编造），
   任何一项不过就不改；连"复核没跑成功"也算不通过；
7. 报告里每条外部证据都可点击、可追溯，并附原始响应留档路径；输出「修正前 vs 修正后」全文对照。

### 现在还不能做什么（重要）

| 做不到的事 | 什么时候能补上 |
| --- | --- |
| 阅读论文**全文**（现在最多读到摘要） | 可做但未做：arXiv / 开放获取全文解析留到后续 |
| 核验中文文献（没有 DOI 的中文来源） | **不在计划内**——Crossref/OpenAlex 没有中文库的公开 API |
| 核验非学术的日常事实（新闻、政策、产品参数） | 需要付费检索服务，暂不做 |
| 在人工标注集上给出精确率、误报率 | 阶段 6 |

> **核心边界**：「文献是真的」和「文献真的这么说」是**两个问题**；
> 「改了」和「改对了」也是**两个问题**——所以修正必须过独立复核才允许进正文。

> **核心边界**：「文献是真的」和「文献真的这么说」是**两个问题**。
> 只有元数据时，系统只回答前者；要回答后者必须有摘要或全文。

## 二、快速开始（Windows / PowerShell）

```powershell
cd <项目目录>

# 1) 环境自检（含大模型密钥连通性，会发一次极小请求）
.\.venv\Scripts\python.exe scripts\check_env.py --network
.\.venv\Scripts\python.exe scripts\check_llm.py

# 2) 不开网页先跑一遍（推荐先做这步）
.\.venv\Scripts\python.exe scripts\run_demo.py --list
.\.venv\Scripts\python.exe scripts\run_demo.py --id internal_conflict

# 3) 启动界面
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

浏览器打开后：首页 → 「检测工作台」载入示例 → 「开始检测」→ 「检测报告」。

| 脚本 | 检查什么 |

| `scripts/check_env.py --network` | Python 版本、依赖、配置、数据目录、Crossref/OpenAlex/arXiv 连通性 |

| 示例 | 演示什么 | 真实结果 |
| --- | --- | --- |
| `real_doi_wrong_claim` | 真实 DOI + 年份写错 | Crossref 与 OpenAlex 都查出 `10.1038/nature12373` 实际发表于 **2013 年**（标题 *Nanometre-scale thermometry in a living cell*），而样例写的是 2008 年 → **「存在矛盾 / 时间信息错误」**（`E2`，严重度高，附两条可点击证据）；同一 DOI 判定为**「已核实」**（只核实"存在"这一层面）；内容类主张因为没有摘要 → `N6`「证据不足」。**阶段 5 实测**：修正员给出"2008 年 → 2013 年"（三项确定性检查全通过），但**复核员否决了它**，理由是"该 DOI 的真实标题是纳米尺度测温，与原文声称的钙钛矿太阳能电池主题不符，只改年份等于默认了这个错误的文献对应关系"——最终**不采用**该修正，并把两个真正未解决的问题写进报告 ✅ |
| `fake_doi` | 虚构 DOI + 数值夸大 | 6 条主张。DOI 前缀不合规 → `N5`（疑似引用不存在）；`提高 40%` 无出处 → `N2`；因果类结论 → `N3`。**检索 0 次**——因为格式不合规的 DOI 根本不能提交给注册机构，系统明确写出了这个理由 |
| `internal_conflict` | 文内自相矛盾 | 7 条主张，**4 条「来源冲突」**（同一 DOI 两个年份 → `I1`；同一指标两个数值 → `I2`），证据来自原文自身 |
| `insufficient_evidence` | 模糊权威 + 预测 | **3 条判「暂无法核验」**（观点/预测，`U1`，**不判成事实错误**）；「多项研究表明」→ `N4`；因果结论 → `N3`+`N4` |

**怎么读这张表**（三条都重要）：

1. **B0 的误报率 44.9%**：直接把文本交给模型判断时，接近一半的**正确内容**被判成有问题。
   这是「模型自评不可靠」最直接的实证——它不是漏检，而是**冤枉**。
2. **B0 的证据可追溯率为 0**：这是它的定义（不给任何外部证据），不是缺陷。
   它意味着每条结论都无法被追问——而这正是本项目要解决的问题。
3. **B1 与 B0 互补**：B1（规则引擎）精确率 100%、误报率 0%，但召回率只有 21.6%；
   B0 召回率更高却误报严重。**B2 同时把两者压到可接受区间**（精确率 97.6%、
   误报率 2.0%、召回率 78.4%）。

**B0 的实现方式（可复核）**：同一个模型（deepseek-chat）、单次调用、不给任何检索工具，
提示词明确要求「不确定时如实选证据不足，不要编造文献」——即"直接问模型"的真实形态。
B0 的结论在数据结构上必须显式标记 `judged_without_evidence=True` 并写明理由，
否则会被数据契约直接拒绝——**系统不允许出现"看起来有证据、其实没有"的结论**。

## 六、裁决规则表（报告里会原文展示命中的规则）

**可解释性是本项目的核心设计**：大模型只输出结构化的"怀疑方向"，
「这条主张到底算不算有问题」由下表决定。因此每条结论都能说清"凭什么"。

| 规则 | 条件 | 结论 |
| --- | --- | --- |
| `I1` | 同一 DOI 在原文中被写成两个不同年份 | 来源冲突（证据来自原文自身，严重度高） |
| `I2` | 同一指标在原文中出现两个不同数值 | 来源冲突（证据来自原文自身，严重度高） |
| `I3` | 两个外部来源对「文献是否存在」给出不一致答案 | 来源冲突 |
| `I4` | 两个外部来源对同一条书目信息给出不一致答案 | 来源冲突 |
| `U1` | 观点 / 预测类内容 | 暂无法核验（**不判成事实错误**） |
| `E1` | 注册机构明确回答「未收录该 DOI」 | 存在矛盾 + 引用不存在（严重度高） |
| `E2` | 权威元数据与原文所述年份 / 期刊不一致 | 存在矛盾 + 时间、人物或机构信息错误（严重度高） |
| `E3` | 文献摘要明确反驳原文结论 | 存在矛盾 + 引用与结论不匹配（数值类为数据错误） |
| `E4` | 摘要只支持结论的一部分（方向对、数值或口径不同） | 部分支持 |
| `E5` | 注册机构中确实存在该文献 | 已核实（**仅限"文献是否存在"这一层面**） |
| `E6` | 权威元数据与原文书目信息一致 | 已核实 |
| `E7` | 摘要明确支持原文主张（且引用了原句） | 已核实 |
| `N0` | 对外部来源的检索**全部失败**（网络 / 服务端故障） | 暂无法核验（这与"没查到"不是一回事） |
| `N1` | 需要外部证据，但本次检索没有获得证据 | 证据不足（**不附带任何问题类型**） |
| `N2` | 主张片段里**确实含数值**，整句却没有可核验出处 | 证据不足 + 缺少必要证据 |
| `N3` | 强因果 / 结论性表述，却没有具体来源 | 证据不足 + 逻辑推断过度 |
| `N4` | 用「大量研究表明」这类模糊表述支撑结论 | 证据不足 + 缺少必要证据 |
| `N5` | DOI 格式不合法（前缀应为 4~9 位数字） | 证据不足 + 引用不存在或元数据不匹配（**疑似，未证实**） |
| `N6` | 找到了对应文献，但拿不到摘要 / 全文 | 证据不足 + 缺少必要证据（**不因为"查到了论文"就默认它支持原文**） |

## 七、配置说明（`.env`）

配置项统一以 `VERIMIND_` 开头；`.env` 已被 `.gitignore` 忽略，**不会提交到 Git**。

```ini
# 大模型：换供应商只改这三行，代码不用动
VERIMIND_LLM_PROVIDER=deepseek                       # mock / deepseek / zhipu / moonshot / dashscope / openai / ollama
VERIMIND_LLM_BASE_URL=https://api.deepseek.com/v1
VERIMIND_LLM_MODEL=deepseek-chat
VERIMIND_LLM_API_KEY=sk-...                          # 留空 = 自动进入离线模拟模式

# 独立复核员（可选）：三项都填且与主模型不同 → 升级为"多模型协同"
VERIMIND_LLM_REVIEWER_PROVIDER=
VERIMIND_LLM_REVIEWER_MODEL=
VERIMIND_LLM_REVIEWER_API_KEY=

# 成本与稳定性
VERIMIND_LLM_TIMEOUT_SECONDS=60
VERIMIND_LLM_MAX_RETRIES=2
VERIMIND_LLM_CACHE_ENABLED=true                      # 相同输入复用缓存，重跑不花钱
VERIMIND_LLM_MAX_CALLS_PER_RUN=30                    # 单次检测调用硬上限

# 成本估算（**故意留空**：没有单价就不显示金额，绝不编一个数字）
VERIMIND_LLM_PRICE_PROMPT_PER_MTOK=                  # 每百万 prompt token 多少元（查官网填）
VERIMIND_LLM_PRICE_COMPLETION_PER_MTOK=

# 外部文献检索（全部免密钥，无需注册）
VERIMIND_RETRIEVE_ENABLED=true
VERIMIND_RETRIEVAL_MAILTO=your-email@example.com     # 建议填真实邮箱：Crossref/OpenAlex 的"礼貌池"会更快更稳
VERIMIND_RETRIEVAL_MIN_INTERVAL_SECONDS=1.0          # 同一来源的请求最小间隔（对公共接口保持礼貌）
VERIMIND_RETRIEVAL_CACHE_HOURS=24                    # 检索结果缓存时长
VERIMIND_RETRIEVAL_MAX_QUERIES_PER_RUN=12            # 单次检测最多执行多少个检索查询
```

填单价后，报告与「检测报告」页会显示按实测 token 计算的成本，并注明"单价来自 .env，请自行核对"。

> ⚠️ **编辑 `.env` 请用记事本或 VS Code，保存为 UTF-8**。
> Windows PowerShell 的 `Set-Content` 在某些环境下默认使用 GBK 编码，会把文件里的中文注释写坏
> （开发期真实踩过这个坑）。用记事本保存没有任何问题。

## 八、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 报错「已选择 provider=... 但没有配置 API Key」 | 在 `.env` 填 `VERIMIND_LLM_API_KEY`，或把 provider 改回 `mock` |
| 报错 HTTP 401 | 密钥无效或已失效（运行 `scripts/check_llm.py` 会直接告诉你） |
| 报错 HTTP 402 | 账户余额不足 |
| 报错 HTTP 404 | 模型名或接口地址不对，核对 `VERIMIND_LLM_MODEL` / `VERIMIND_LLM_BASE_URL` |
| 报告顶部出现「⚠️ 本次已降级为离线规则引擎」 | 模型调用失败（超时/限流/格式连续不合格），系统自动降级**并声明原因**，不会假装调用成功 |
| 中文文献为什么总是「暂无法核验」 | Crossref / OpenAlex 收录的是学术元数据，**没有中文库的公开 API**。没有 DOI 的中文来源无法有效检索——系统会写明"查过了、没命中"，而不是硬凑结论 |
| 为什么说"文献已核实"却不说"结论正确" | 这是刻意的：「文献是真的」与「文献真的这么说」是两个问题。只有摘要/全文层面的证据才能判断后者 |
| 为什么有的证据标着"仅元数据 / 未做判断" | 那是查到的文献记录，但拿不到摘要——系统只用它核验存在性与书目信息，并如实标出"这一层面没做判断" |
| 报告里说「N 次命中缓存」 | 同一段文本之前跑过；缓存键包含提示词版本，改了提示词会自动失效。检索结果同样默认缓存 24 小时 |
| 为什么有些主张标了问题类型却不叫「已判定有问题」 | 「已判定有问题」只统计状态为存在矛盾/部分支持/来源冲突的；其余是「需关注」（疑似或证据缺口），两个数字分开显示，避免夸大检测能力 |
| 历史记录打不开，提示"旧版本数据结构" | 数据契约升级过；删掉 `data/verimind.db` 重新检测即可（该文件不在 Git 里） |
| 命令行中文乱码 | `chcp 65001`，或用 `.\run.ps1` 启动（已自动处理） |
| 编辑 `.env` 后变成乱码 | **不要用 PowerShell 的 `Set-Content` 保存 `.env`**（默认编码可能是 GBK）。用记事本 / VS Code 保存为 UTF-8 |
| 端口被占用 | `--server.port 8600` 换端口 |

## 九、设计原则（贯穿整个项目）

1. **证据可追溯**：每条判断都要能点开到真实来源，并附原始响应留档路径；报告里不出现无法解释的结论。
2. **区分判断层面**：文献是否存在 / 书目信息是否一致 / 内容结论是否被支持——三个层面分开回答，不许越界。
3. **模型不下最终结论**：模型只输出结构化判断与"怀疑方向"，状态由可解释的规则表裁决。
4. **暴露分歧，不掩盖分歧**：规则引擎与模型、Crossref 与 OpenAlex 之间的不一致，全部写进报告。
5. **无证据不判错**：「证据不足 / 暂无法核验」是一等公民，绝不为了凑结论把"查不到"说成"错误"。
6. **不存在 vs 查不到必须分开**：注册机构明确 404 才可以判"引用不存在"；网络失败只能说"暂无法核验"。
7. **引用必须可复核**：模型判断"支持/反驳"必须给出摘要里的原句，程序会验证它真的在原文中；编造的引用一律丢弃。
8. **改错比不改更糟**：修正必须过独立复核才允许进正文；复核没通过、甚至没跑成功，都不改。
   其中三项检查由代码完成（是否有证据、新数字是否与所引证据匹配、是否凭空编造），模型无法推翻。
9. **失败要说出来**：模型调用失败就明确降级并声明原因，绝不悄悄用规则结果冒充模型结果。
10. **不给假数字**：没有校准过的概率就不给"幻觉分数"；没有配置单价就不给成本金额；只报真实 token、检索次数与耗时。
11. **不注水**：一句话不会拆成好几条同义主张；宁可报"需要关注"，也不虚报"已判定有问题"。
12. **密钥安全**：密钥不写入代码、不进 Git、不出现在日志与报告中（日志只记提示词哈希）。
